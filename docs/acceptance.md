## 准备

1. 记录候选版 `version` 输出和 SHA256，复制 `examples/` 中对应配置，替换服务器、认证域和用户。每客户独立配置、端口和状态目录；密码通过终端或 secret 文件提供。
2. 先 `config-check`，aTrust 再运行 `auth-info` 确认认证域；处理私有 CA 或可信渠道取得的 pin。需要 EC 旧 TLS 通道的客户单独确认并设置例外。
3. 同账号比较新旧客户端时交替登录，避免网关单会话规则影响结论。记录原 docker-easyconnect 的镜像、容器名、端口与配置路径，保留原状态。
4. 先前台认证，确认进入 `ready`，再通过该客户两个代理端口执行实际业务。`ready` 本身不代表应用权限、DNS 和业务都已验证。

## 每客户记录

| 检查 | 操作 | 必须记录 |
|---|---|---|
| 认证 | 正确/错误密码、图片、点选、短信/TOTP、取消及过期；按客户实际流程覆盖 | 是否发送一次、错误码、等待状态、是否可再次前台接管 |
| 代理 | HTTP、HTTPS CONNECT、SOCKS5h；域名和 IP；大文件双向传输、长连接 | 业务成功标准、文件校验和、连接错误 |
| DNS/授权 | 内部域名、无 DNS、失败域名、未授权地址、IPv6 | 明确失败，无公共 DNS 或本地直连兜底 |
| 隔离 | A/B/C 同时运行，包含相同私网 IP；分别访问能辨别客户的内容 | 目标属于正确客户；停止 A 后 B/C 持续成功 |
| 恢复 | 临时断网、网关下线、服务端撤销会话；重新恢复网络 | 旧 TCP 已关闭；次数有界；新代次；认证失效返回 3，不循环短信 |
| 凭据 | 开关关闭、存储锁定/不可用、错误 age 口令、改账户、改密、忘记密码与清会话 | 不读关闭的记录、不跨绑定、无明文降级 |
| 稳定性 | 8 小时业务，另测至少 60 分钟无业务后恢复 | 每实例 CPU/RSS/连接数、失败时间、吞吐与基线对比 |
| 回退 | 停止 tinyrill，恢复原代理选择与旧客户端 | 旧配置/状态未变，原业务恢复 |

可复制 `examples/acceptance-targets.json` 到 `local/`，填入无认证参数的只读健康检查 URL，运行 `pwsh scripts/soak.ps1 -TargetsFile local/acceptance-targets.json`。脚本只探测已有代理，不登录、不自动发送验证码、不启动 VPN；将每次状态、耗时和可选 PID 的工作集/CPU 累计值写入本地 JSONL。该探测不能替代长连接、大文件、空闲及业务内容正确性验收。

请记录脱敏的客户代号、部署方式、网关/客户端版本参考、实际认证链、候选提交、预期与实际行为。不要提交 session.json、验证码原图、密码、Cookie、token、SignKey、证书私钥或含认证参数的完整 URL。正常和 debug 日志只含诊断元数据；交互终端会显示必要的认证链接及验证码，应避免录屏或重定向到共享日志。

## 回退

Ctrl+C 停止原生实例，或 `podman stop <本次容器名>`，确认其代理端口释放。将应用/mihomo 的出站切回原 docker-easyconnect 端口，再启动旧客户端并按需重新认证。首版不迁移、覆盖或删除旧客户端状态。暂时回退无需删除新状态；只有明确要注销本地复用状态时执行 `session clear`，忘记保存的密码另外执行 `credentials delete`。这些命令不替代网关侧注销其他会话。
