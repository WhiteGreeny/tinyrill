# 认证诊断交付：0.1.0-rc.5-diagnostic.2

日期：2026-11-18。本次提供 Windows/Linux amd64 原生诊断包，程序及源码固定于 `9eec72b6c00fd5046df9d460b484c56c8378f62f`，Go 1.27.4。用途是采集客户密码过期、强制改密或未知认证步骤的现场证据；不实施密码过期判定或服务器改密。

## 使用方法

```powershell
.\tinyrill.exe run --config .\customer.yaml --auth-debug
```

Linux 使用 `./tinyrill run --config ./customer.yaml --auth-debug`。沿用自己的配置和状态目录；该开关默认关闭，无需修改 YAML 或启用普通 debug。运行包仍为 7 个文件，运行说明已包含认证诊断操作。

问题出现后，按终端提示找到状态目录中的 `auth-debug.json`，**先复制再重启**。诊断运行会替换旧报告，最多保留本次最近 64 次认证请求。检查时间/版本，人工复核字段名及服务名后再分享；不需要配置、会话、凭据或完整终端日志。详细范围见 [认证诊断说明](auth-diagnostics.md)。

文件保留已知响应位置中的返回码、后续服务标识、有限字段结构及固定词表线索。请求正文、头、原始网关提示、认证秘密与未知字段原值不导出；同名 `code` 出现在未知对象或 aTrust `data.code` 时也不保留值。正常认证流程随后解析失败时，已取得的诊断仍会保留。没有自动密码重试，也没有新增网络请求。
